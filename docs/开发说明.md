# 开发说明

这份给人看，说明**从零把 InnoScale 在本机跑起来**、日常怎么改、以及线上怎么部署。Cursor 改代码时读的是仓库根目录的 `AGENTS.md`；那份文件必须留在根目录。

## 先读这三条

1. **只用 Docker 跑应用。** 不要用 `npm run dev`、`npm run dev:no-auth`、`npm start` 或 PM2 启动服务。宿主机上的 `npm` 只做 lint / test / `tsc` / 生成迁移。
2. **没有预发环境。** 线上 Ubuntu 虚拟机就是生产。本地容器验证通过之前，不要跑 `./scripts/docker-up-online.sh`，也不要改线上 env 或在线上容器里试迁移。
3. **秘钥不进 Git。** 可提交的是 `config/secrets/*.env`（里面是 `ssm:...` 引用）。本机真正用的是 `.env.docker.local` / `.env.docker.online`，由启动脚本生成，不要提交。

产品名是 **InnoScale**。仓库：https://github.com/SpectrAI-Initiative/InnoScale

## 从零开始：本地开发

按顺序做。目标：浏览器打开 http://127.0.0.1:3000 能注册/登录、进工作区。

### 1. 准备机器

| 需要 | 说明 |
|------|------|
| Git | 用来克隆仓库 |
| Docker Desktop（Windows/macOS）或 Docker Engine 24+ 与 Compose v2（Linux） | 构建并运行应用容器 |
| MySQL 8.0.13+（宿主机进程） | 本地默认连 `127.0.0.1:3306`，**不是** Compose 里的 MySQL 服务 |
| Node.js 24+（可选但推荐） | 只在宿主机跑检查命令；不负责启动 Web 服务 |
| 模型 API Key | 至少要有可用的 `DEEPSEEK_API_KEY`（或你们配置的等价密钥），否则页面能开但对话不可用 |
| 腾讯云 API 密钥（可选） | 若要用仓库里已有的 SSM 密封配置自动灌秘钥：环境变量 `TENCENTCLOUD_SECRET_ID` / `TENCENTCLOUD_SECRET_KEY`，或把 `SecretKey.csv` 放在桌面 |

Windows 上 Docker 镜像存在 Docker Desktop 虚拟盘（例如 `%LOCALAPPDATA%\Docker\wsl\disk\docker_data.vhdx`），不在仓库目录里。

### 2. 获取代码

```bash
git clone https://github.com/SpectrAI-Initiative/InnoScale.git
cd InnoScale
```

后续命令都在**仓库根目录**执行。

### 3. 准备本机 MySQL

本地默认连接串：

```text
mysql://innoscale:innoscale-local@host.docker.internal:3306/innoscale
```

容器经 `host.docker.internal` 访问宿主机上的 MySQL。请先在本机保证：

1. MySQL 在 `127.0.0.1:3306` 监听。
2. 存在库 `innoscale`（建议 `utf8mb4` / `utf8mb4_bin`）。
3. 存在用户 `innoscale`，密码 `innoscale-local`，且对该库有足够权限（含迁移所需的 `ALTER`）。

可用 root 一次性创建（按你本机认证方式调整）：

```sql
CREATE DATABASE IF NOT EXISTS innoscale CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;
CREATE USER IF NOT EXISTS 'innoscale'@'%' IDENTIFIED BY 'innoscale-local';
CREATE USER IF NOT EXISTS 'innoscale'@'localhost' IDENTIFIED BY 'innoscale-local';
GRANT ALL PRIVILEGES ON innoscale.* TO 'innoscale'@'%';
GRANT ALL PRIVILEGES ON innoscale.* TO 'innoscale'@'localhost';
FLUSH PRIVILEGES;
```

`docker-up-local` 会检查 3306；若 MySQL 没起来，脚本会尝试拉起本机 `mysqld`（Windows 可设 `LOCAL_MYSQL_HOME`，或把安装放在仓库 `.runtime/mysql/<version>/`）。**库和用户仍需你事先建好**（或把 `.env.docker.local` 里的 `DATABASE_URL` 改成已有账号）。

表结构在容器启动时自动迁移，细节见 [database.md](database.md)。

### 4. 配置环境与密钥

有两种路径，二选一即可。

#### 路径 A：用腾讯云 SSM（团队已有密封配置时）

仓库里已有 `config/secrets/docker.local.env`，头部类似：

```text
# ssm-secret=innoscale-docker-local
AUTH_SECRET=ssm:AUTH_SECRET
DEEPSEEK_API_KEY=ssm:DEEPSEEK_API_KEY
```

准备好腾讯云访问密钥后，直接跑启动脚本即可：脚本会把秘钥 materialize 到 `.env.docker.local`，并补上 `DATABASE_URL`。

#### 路径 B：纯本机明文（个人从零、暂时不用 SSM）

若没有密封配置、也没有 `.env.docker.local`，第一次执行启动脚本会生成 `.env.docker.local`。生成后请打开该文件，至少确认：

| 变量 | 含义 | 本地常见值 |
|------|------|------------|
| `PUBLISH_PORT` | 宿主机端口 | `3000` |
| `HOST_WORKSPACE_PATH` | 挂进容器的研究目录（宿主机路径） | `./workspace` |
| `WORKSPACE_ROOTS` | 容器内允许的工作区根 | `/research` |
| `AUTH_MODE` | 鉴权 | `local`（仅本人机器可临时 `disabled`） |
| `AUTH_COOKIE_SECURE` | Cookie 是否要求 HTTPS | 本地 HTTP 用 `false` |
| `AUTH_SECRET` | 会话签名密钥 | 长随机串 |
| `DEEPSEEK_API_KEY` | 模型密钥 | 换成真实 key，不要留 `none` |
| `DEEPSEEK_BASE_URL` | 模型 API 地址 | 按你们网关填写 |
| `LLM_PROVIDER` / `LLM_MODEL` | 默认模型 | 如 `deepseek` / 具体模型名 |
| `DATABASE_URL` | MySQL | 见上一节默认串 |

改完再执行一次启动脚本。

把本机明文封进 SSM（有腾讯云权限时）：

```powershell
.\scripts\ssm-env.ps1 publish .env.docker.local config/secrets/docker.local.env innoscale-docker-local
```

```bash
./scripts/ssm-env.sh publish .env.docker.local config/secrets/docker.local.env innoscale-docker-local
```

### 5. 构建基础镜像（首次必做）

应用镜像基于本地标签 `innoscale-base:24.04-node24.22.3`（Ubuntu 24.04 + Node 24.22.3 + 编译依赖 + tini）。定义在 `Dockerfile.base`。

```powershell
.\scripts\docker-build-base.ps1
```

```bash
chmod +x scripts/docker-build-base.sh
./scripts/docker-build-base.sh
```

首次可能要十几分钟（拉 Ubuntu、装 apt、装 Node）。之后除非升级 Node/系统包，否则不用重做。  
若忘记这一步，`docker-up-local` 发现缺少基础镜像时会自动构建。可用 `BASE_IMAGE` / `INNOSCALE_BASE_IMAGE` 覆盖标签；构建基础层时可用 `UBUNTU_IMAGE` 换 Ubuntu 源（默认 `docker.1ms.run/library/ubuntu:24.04`）。

### 6. 启动本地应用

Windows：

```powershell
.\scripts\docker-up-local.ps1
```

Ubuntu：

```bash
chmod +x scripts/docker-up-local.sh
./scripts/docker-up-local.sh
```

脚本会：

1. （若有密封配置）从 SSM 写出 `.env.docker.local`
2. 校正 `DATABASE_URL` 指向宿主机 MySQL
3. 检查并尽量拉起本机 MySQL
4. 设置 `COMPOSE_PROJECT_NAME=innoscale`（容器名不跟文件夹名走）
5. 缺少基础镜像则先构建
6. `docker compose ... up -d --build --no-deps innoscale`
7. 检查 http://127.0.0.1:3000

第一次完整应用构建大约十几分钟（主要是 `npm ci` 与 Next 生产构建）；依赖与源码未变时后续会快很多。

浏览器打开：**http://127.0.0.1:3000**

### 7. 本地验收清单

1. 页面能打开  
2. 注册或登录后能进工作区列表；进入空间后，技能库、文献库、Deep Research、设置可用  
3. 发一条对话，模型有返回（确认 API Key 有效）

### 8. 日常怎么改代码

- 改的是**宿主机源码**；容器里是上次构建的镜像，**没有热更新**。
- 改完后重新执行 `docker-up-local`（会 `--build` 并重启）。
- 宿主机检查（不启动服务）：

```bash
npm install
npx tsc --noEmit
npm run lint
npm test
```

- 改了 `src/lib/db/schema.ts`：在宿主机 `npx drizzle-kit generate`，提交 `drizzle/` 新文件；迁移在容器启动时自动跑。见 [database.md](database.md)。
- 代码约定见根目录 `AGENTS.md`。

### 9. 日志与停止

```powershell
docker compose --env-file .env.docker.local -f docker-compose.yml -f docker-compose.local.yml logs -f innoscale
docker compose --env-file .env.docker.local -f docker-compose.yml -f docker-compose.local.yml down
```

## 两套环境对照

| | 本地 | 线上（生产） |
|------|------|----------------|
| 配置 | `.env.docker.local` | `.env.docker.online` |
| 密封配置 | `config/secrets/docker.local.env` | `config/secrets/docker.online.env` |
| SSM 凭据名 | `innoscale-docker-local` | `innoscale-docker-online` |
| 启动 | Windows：`.\scripts\docker-up-local.ps1`；Ubuntu：`./scripts/docker-up-local.sh` | `./scripts/docker-up-online.sh` |
| Compose | `docker-compose.yml` + `docker-compose.local.yml` | `docker-compose.yml` + `docker-compose.online.yml` |
| 访问 | http://127.0.0.1:3000 | `http://<虚拟机IP>:3000` |
| 端口 | 只绑定 `127.0.0.1` | 发布到虚拟机网卡 |
| 数据库 | 宿主机 MySQL → `host.docker.internal` | 腾讯云 MySQL 内网 |
| 工作区挂载 | 默认 `./workspace` → `/research` | 默认 `/data/innoscale/research` → `/research` |

Compose 服务名 / 项目名：`innoscale`。应用数据卷：`innoscale-data`。

## 没有预发环境

线上虚拟机就是生产。下面这些都算直接动生产，本地验证前不要做：

- 线上 `git pull` 后执行 `./scripts/docker-up-online.sh`
- 手改线上 `.env.docker.online` 后重启
- 在线上容器里试迁移、清库、换密钥或换镜像

## 工作台的控制面和数据面

改界面时先分清改的是「屏幕状态」还是「内容数据」。

控制面只回答屏幕状态，实现在 `src/lib/shell/surface.ts`。工作区页 `/workspace/:id` 的查询参数由 `parseShellSurface` / `buildWorkspaceHref` 读写。

| 参数 | 含义 |
|------|------|
| `view` | `agent`、`skills`、`library`、`research`、`settings`；缺省 `agent` |
| `research` | 当前 Deep Research 会话（仅 `view=research` 且非新建） |
| `intake=1` | Deep Research 新建入口 |
| `file` | 右侧预览路径（仅 `view=agent`） |

| 屏幕上的东西 | 数据从哪里来 |
|--------------|----------------|
| 项目 | `/api/workspaces` |
| Agent 会话 | 浏览器 `localStorage`（按账号隔离） |
| Deep Research | `/api/deep-research/sessions` |
| 技能库 | `/api/skills` |
| 文献检索 | `POST /api/paper-study/search` |
| 预览文件 | 工作区文件接口 |

## 线上部署

只部署已在本地容器验证过的版本。虚拟机需 Docker Engine 24+、Compose v2，以及能访问腾讯云 SSM / MySQL 的网络与密钥。

```bash
chmod +x scripts/docker-up-online.sh
./scripts/docker-up-online.sh
```

有 `config/secrets/docker.online.env` 时，从 SSM **`innoscale-docker-online`** 写出 `.env.docker.online`。当前密封配置托管 `AUTH_SECRET`、`DEEPSEEK_API_KEY`；`DATABASE_URL` 若为空，部署前写入明文后再 publish：

```bash
./scripts/ssm-env.sh publish .env.docker.online config/secrets/docker.online.env innoscale-docker-online
```

至少保证：

- `DATABASE_URL`：腾讯云 MySQL 内网连接串（见 [database.md](database.md)）
- `DEEPSEEK_API_KEY`
- `HOST_WORKSPACE_PATH`：虚拟机上真实目录
- `WORKSPACE_ROOTS=/research`
- `AUTH_SECRET`
- `AUTH_MODE=local`
- `AUTH_COOKIE_SECURE=false`（上 HTTPS 后再改为 `true`）

线上同样依赖 `innoscale-base:24.04-node24.22.3`；缺失时启动脚本会先构建。

`AUTH_SINGLE_ADMIN=true` 时，首次引导管理员：

```bash
umask 077
openssl rand -base64 32 > /tmp/innoscale-admin-password
docker compose --env-file .env.docker.online -f docker-compose.yml -f docker-compose.online.yml exec -T innoscale \
  node /app/admin-cli/scripts/bootstrap-admin.js \
  --email admin@example.com --name Administrator \
  < /tmp/innoscale-admin-password
```

升级：本地验证 → 虚拟机备份 → `git pull` → `./scripts/docker-up-online.sh`。保留上一版镜像直到登录、工作区、模型回复都正常。

需要 HTTPS 时用 Nginx/Caddy 反代到 `127.0.0.1:3000`，并转发 `Upgrade`（否则流式会被掐断）。

```bash
docker compose --env-file .env.docker.online -f docker-compose.yml -f docker-compose.online.yml down
docker compose --env-file .env.docker.online -f docker-compose.yml -f docker-compose.online.yml logs -f innoscale
```

## 排错

| 现象 | 处理 |
|------|------|
| `workspace root missing` | 宿主机上要有 `HOST_WORKSPACE_PATH`；容器内根一般是 `/research` |
| `no AI API key detected` | 检查 `.env.docker.*` 里的 `DEEPSEEK_API_KEY`，或 SSM materialize 是否成功 |
| SSM 取秘钥失败 | 凭据名、区域 `ap-shanghai`、调用方 `GetSecretValue` 权限；桌面是否有 `SecretKey.csv` |
| `FROM innoscale-base` 失败 | 先跑 `docker-build-base`，或设 `BASE_IMAGE` |
| 拉 Ubuntu 401 | 换 `UBUNTU_IMAGE` 后重跑 `docker-build-base`（默认已用 `docker.1ms.run`） |
| 容器马上退出 | `docker compose ... logs innoscale` |
| `DATABASE_URL must be a mysql://...` | 不要填 SQLite 路径；用 MySQL 连接串 |
| 连不上库 | 本机 `127.0.0.1:3306` 是否有 mysqld、库/用户是否为 `innoscale`；容器是否用 `host.docker.internal` |
| 端口被占用 | 改 `PUBLISH_PORT` |

改代码时的仓库约定见 `AGENTS.md`。
